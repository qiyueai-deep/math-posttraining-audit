中文数学大模型后训练算法与可信评估

技术报告：一条 LoRA-SFT + DPO 链路，以及一次「指标上升、能力退化」的归因

代码：math-posttraining-project-v2　·　数据 seed 20251109　·　 指标源：reports/results.jsonl（245 条记录，9 条为 Qwen 权重层待运行）

摘要. 本项目构建一条中文数学后训练链路，包含参数化题目生成、严格三态验证器、 LoRA-SFT、三组对照偏好数据、DPO 与四个泛化子集上的生成评测。起点是一次失败复现： 旧项目训练损失与 reward margin 单调下降或上升，自由生成的符号准确率却由 62.5% 退回 50%。 审计把原因定位到三处测量失效：40 条测试集实际只含 2 道独立题，旧评测器判对的 65 条中 32 条是假阳性，240 条偏好对里没有一条含真实数学错误。为了在没有 GPU 的机器上验证 目标函数层面的机制，构建了 7 维可解析梯度的 log-linear 策略实验台，SFT 与 DPO 均为 真实训练，解析梯度经中心有限差分校验（最大误差 3.44e-11）。三组偏好对照的 reward accuracy 同为 1.0000，长度偏置劫持率分别为 0.7241、0.1864、0.0720， 参考模型锚错使 KL 由 0.0513 升至 0.5179。三个测量问题各自给出估计量与区间： 表面特征 AUC 从 1.0000 降到 0.5000，设计效应 15 对应有效样本量 2.6667， 验证器 FPR 0.5000 使观测准确率 0.7425 被校正为 0.6496。Qwen3-0.6B 的权重训练尚未运行， 9 个模型指标保持 pending，不在本报告中给出数值。

1　问题与起点

旧项目报告了两组互相矛盾的证据。一方面，teacher-forced loss 从 4.41 降到 2.50， reward margin 随 beta 单调上升；另一方面，同一套权重在自由生成下的符号准确率是 Base 50%、SFT 62.5%、DPO 50%，DPO 把 SFT 的增益退回了起点。更直接的矛盾是， 三份报告对同一个模型给出三个不同的 perplexity 数值，极差 42.0887， 而仓库里保存的 adapter 无法复现其中任何一组最好看的数字。

把现象拆成三个可检验的假设，比笼统地说「调参失败」更有用：

  • H1 数据不承载质量信号。偏好对的标签可以由长度与格式线索完全预测， 梯度方向与真实数学质量无关。
  • H2 评测器有系统性误判。子串包含式的判对把推导里出现的数字当成答案， 观测准确率高于真实准确率。
  • H3 推断单位错误。测试集里的 40 条是 2 道题的伪重复， 把簇内完全相关的样本当独立样本会把方差低估一个数量级。

2　后训练链路

2.1　数据构造与切分

题目由 12 个参数化题型族生成，每题参数唯一，答案先由题型族自带的 oracle 计算， 再用第二条独立计算路径交叉验证，不一致直接抛错。切分以题型族与参数签名为单位， 而不是以字符串为单位，这样「同题改写」不会跨 split 泄漏。测试集额外拆成四个子集： 未见参数、同义改写、反事实（改动条件后重算答案）、未见题型族。

2.2　三态评测器

答案比较不使用子串包含。做法是把候选答案与标准答案都解析成受限语法的表达式 （支持整数、分数、小数、逗号分隔的多解、单变量多项式），在有理数域上做精确相等， 必要时对多项式做规范形比较。解析失败抛 ParseError，由上层记为 unverifiable，不回退到字符串匹配。判定因此是三态： correct、incorrect、unverifiable。 第三态单独统计，不折进错误率。

这个选择的代价是覆盖率。旧项目 120 条生成输出里有 87 条不可核验， 主要因为解码在 64 token 处截断，答案标记没写完。新协议把 max_new_tokens 固定为 256，并把这个比例作为独立指标报告， 而不是把它当成「答错」来压低准确率。

2.3　SFT 的 assistant-only loss

对话样本由 prompt 与 assistant completion 拼接。旧实现对整段序列计算 NLL， 模型只需记住重复出现的题干就能把 loss 压低，指标与数学能力脱钩。 修正版用 chat template 分别渲染完整对话与只到 prompt 的文本，断言前者以后者为前缀， 再用 fast tokenizer 的 offset_mapping 在字符级定位边界， 把起点小于 prompt 长度的 token 的 label 置为 -100。总 NLL 按 completion token 加权， 训练与验证共用同一 mask。

2.4　三组对照偏好数据

三组数据回答同一个问题：DPO 的梯度到底花在哪个特征上。shortcut 组复刻旧项目的缺陷， rejected 更短、答案其实正确。deconfounded 组把长度与格式严格对齐，只改数学内容， rejected 是把推导里所有答案出现处等长替换为错误值，长度差恒为 0、格式标记一致。 length_reversed 组故意反转长度线索，rejected 更长但答案错误。

2.5　DPO 与参考模型

DPO 的参考策略必须是 SFT 模型。TRL 在 ref_model=None 且策略是 PeftModel 时会 disable adapter，KL 锚点于是落在未训练的 base 上， SFT adapter 的参数被当作可直接优化的变量，目标函数不再是原始 DPO。 修正版用独立基座实例加载冻结的 SFT adapter 显式传入，训练前逐参数断言 ref 与 policy 初始一致，并把真正使用的 ref 快照落盘。

(1) L(θ) = −(1/n) Σi log σ( β [ log(πθ(yi+|xi) / πref(yi+|xi)) − log(πθ(yi−|xi) / πref(yi−|xi)) ])

beta 不能只看 reward margin。固定策略时 margin 等于 beta 乘 log-ratio 差， 随 beta 线性增长是恒等式。可报告的量是策略相对参考模型的 KL，以及下游生成准确率。 真实模型里配分函数不可算，KL 用从策略采样的 log πθ − log πref 均值估计，按 prompt 聚类给 bootstrap 区间。

3　算法机制实验台

3.1　为什么单独做一层

没有 GPU 时，权重层的 SFT 与 DPO 无法执行，但目标函数层面的性质仍然可以验证， 前提是配分函数可算。把策略限制为候选集上的 log-linear 模型， log πθ(y|x) = θ·φ(x,y) − log Zθ(x)， 其中 Zθ(x) = Σy∈Y(x) exp(θ·φ(x,y))。 同一 prompt 下 Z 在成对比较里抵消，DPO 的隐式 reward 差、梯度和 KL 都有闭式解。 这一层不替代权重训练，它回答的是「目标函数是否真的在奖励长度」。 算法层、权重层 pilot 与完整协议三层在报告中始终分开标注。

3.2　模型与梯度

特征 φ 取 7 维：字符长度、是否含最终答案标记、LaTeX 标记数、数字个数、标点数、换行数， 以及由严格验证器给出的正确性指示。前 6 维是表面特征，最后一维是质量的可观测代理。 令 Δi = (θ − θref)·(φi+ − φi−)， 式 (1) 化为

(2) L = −(1/n) Σi log σ(β Δi)，　　 ∇θL = −(β/n) Σi (1 − σ(β Δi)) (φi+ − φi−)

式 (2) 是实验台里实际执行的更新，也是有限差分校验的对象。SFT 阶段在 chosen 上做 最大似然，梯度为 Eπθ[φ] − φ(y+)， 得到 θsft 作为 DPO 的策略初值与参考模型。

3.3　设置

SFT 用 252 条指令、120 步、学习率 0.03。 DPO 每组 400 步、学习率 0.08、beta 0.1。下游用 2×2 平衡探针： 正确/错误 × 短/长，短对与短错等长，长对与长错等长，另设一组对抗探针， 让「短的正确」与「明显更长的错误」二选一。所有分数用 softmax 概率加权， 不用硬 argmax，避免平局时按索引取值造成虚高。

4　权重层 CPU pilot（真实 Qwen3-0.6B 权重）

4.1　为什么是三层验证

算法实验台验证的是目标函数，权重层 pilot 验证的是代码链路， 完整协议才用于能力结论，三者不能互相替代。本机没有 GPU，但有 CPU 版 torch 与完整的 Qwen3-0.6B 权重，因此可以在缩减规模下把 LoRA-SFT、显式冻结 SFT 参考模型的 DPO、assistant-only masked NLL、 严格三态验证器的生成评测和序列级 KL 的采样估计真实执行一遍。 pilot 用 configs/model_pilot.yaml 里写明的规模， 逐条记录写在 reports/model_pilot_manifest.json。

参考模型在训练前用独立基座实例加载同一个 SFT adapter， 逐参数断言与 policy 初值一致（检查了 422 个共享参数）， 再把冻结 ref 的成对 log-ratio 预计算缓存。序列级 KL 用从策略采样的 log πθ − log πref 均值估计为 -0.0129，bootstrap 区间 [-0.0497, 0.0238]， 样本量 4，只作量级参考。

pilot 只回答「链路能不能在真实权重上跑通」。 缩减后的样本量与生成长度不足以支持任何关于模型能力的结论， 正式协议的 9 个指标仍为 pending， 本节的任何一个数字都不写进简历的能力陈述。

5　三个测量问题

5.1　偏好信号的可识别性

设 S 为一对回答的表面特征差，Q 为真实质量差，Y 为偏好标签。 若存在可测函数 f 使 Y = f(S) 几乎处处，且 Q ⟂ Y | S，则 DPO 的经验风险不识别 θ 在 Q 方向的分量。证明的要点是构造观测等价的策略扰动： 对数据集中出现的每个回答给对数概率加同一个常数 ci， 把腾出的概率质量重新分配给数据集外的回答，成对差 Δ 与损失 L 逐点不变， 而数据集外的行为可以任意改变。等价地，把 θ 分解为控制数据集内相对概率的 φ 与控制数据集外行为的 ψ，似然只依赖 φ，关于 ψ 的 Fisher 信息为零。

把条件做成可操作的量：只用 6 个表面特征训练逻辑回归， 按偏好对分组做 5 折交叉验证，报告 AUC 与 SI = 2·AUC − 1。

5.2　伪重复与配对推断

40 条测试集来自 2 道题，簇内结果几乎完全一致。用单因素方差分析估簇内相关， 得 ICC 0.7368，设计效应 deff = 1 + (m − 1)ρ = 15， 有效样本量 neff = n / deff = 2.6667。 把 40 条当独立样本得到的正态区间是 [0.0212, 0.2288]，不跨 0； 以题目为聚类单位做 bootstrap 得到 [0.0000, 0.2500]，跨 0。 结论从「显著提升」变成「不能拒绝无提升」。

配对检验给出一致的结论。SFT 对 Base 的 McNemar 精确 p 为 0.0625，三个两两比较做 Holm 校正后最小 p 为 0.1875。按观测到的簇间方差反解功效， 要检出 5 个百分点的提升需要约 99 个独立簇。 现有 2 个簇对应的功效只有 0.0685。

新数据集按题型族做聚类，测试集有 303 条、 12 个族，按同一公式估得的有效样本量在 36.6 到 303.0 之间，取决于簇内相关取中等值还是取 0。这比 40 条对应 2.6667 高两个量级， 但仍然远小于条数本身。

5.3　验证器偏差校正

构造真值 π = 0.6625。旧式验证器把推导里出现的数字当答案， FPR 高达 0.5000，观测准确率高估 0.0800；校正把偏差压到 -0.0129，代价是分母 1 − FPR − FNR 只有 0.3733，区间明显变宽。

没有人工金标准时，可以用多个验证器的判定做潜类别估计。J 个验证器有 2J − 1 个自由模式频率，模型有 1 + 2J 个参数，J = 2 时 3 对 5 欠识别，J = 3 时 7 对 7 恰好识别。 三验证器 EM 给出的 π̂ 是 0.8682，与真值相差 0.0241。代价是覆盖率只有 0.7425，因为只能使用三者都给出二元判定的样本， 被丢掉的几乎都是没有答案标记的错误输出，属于 MNAR。子集真值比全集高 0.2298，这个选择偏差本身就是结论： 直接丢掉不可核验样本再报准确率，会系统性高估。

条件独立是这套估计的硬假设。以 0、0.2、0.5 的概率把第三个验证器的判定替换成第一个， π̂ 从 0.8682 变到 0.8753，幅度 0.0072。在这批数据上结论不敏感， 但这不构成一般性保证。

6　讨论

三处失效不是并列的，它们互相放大。偏好数据里没有真错误，使梯度只能沿表面特征走； 评测器用子串匹配，使「更长、含更多数字」的回答更容易被判对，于是表面特征与观测收益 同向；测试集是伪重复，使这点收益在统计上显得显著。三者叠加，就得到一条 「loss 下降、margin 上升、准确率不动」的曲线。把其中任何一处单独修掉， 另外两处仍会让结论看起来成立，这也是旧项目反复调参却没有进展的原因。

对工业评测，这套诊断可以直接落成三条操作。上线前给偏好数据做体检， 表面特征基线 AUC 接近 1 就说明这批数据只能教格式。评测集做样本量规划， 用簇内相关算有效样本量，别把同题改写当独立样本，否则 A/B 结论的假阳性会失控。 自动评测器定期用一小批人工标注估 FPR/FNR，把观测准确率还原成真实准确率再报。 三件事都不需要额外训练成本。

局限同样明确。实验台的策略是 7 维解析模型，能验证目标函数却不能替代权重训练， 它的探针设计也参与了结论的构造。权重层 CPU pilot 已在真实 Qwen3-0.6B 权重上跑通缩减协议，但完整协议的 9 个指标 仍为 pending。聚类推断只有 2 个簇，簇间方差不可靠， 功效数字只能当量级看。潜类别估计依赖条件独立，敏感性分析只覆盖了一种相关结构。 这些都在结果文件里逐条标注，没有藏在正文之外。

7　复现

研究阶段与算法实验台只用 Python 标准库，不需要 GPU，也不需要安装依赖。 在项目根目录执行：

python -m src.run_all --stage research　　# 数据、算法实验台、三个测量问题、报告
python -m src.run_all --stage algo　　　　# 单独跑解析策略的 SFT → DPO
python -m src.model.pilot　　　　　　　　# 真实 Qwen3-0.6B 权重上的 CPU pilot
python -m src.run_all --stage check　　　 # 三轮检查

产物包括 data/ 下 600 道题与三组偏好数据、 reports/results.jsonl 单一事实源、 reports/research_report.md 指标表、 reports/algo_lab_curves.json 与 algo_lab_curve.svg 训练曲线， 、reports/model_pilot_manifest.json 与逐条预测文件，以及本报告。reports/check_report.json 记录三轮检查： 全量编译与单元测试、报告数字逐条反查、原项目 134 个文件哈希未变。 重跑研究阶段后上述文件的哈希逐字节一致。

权重层分两步。CPU pilot 在有 torch 的解释器上执行 python -m src.model.pilot，或右键 run_model_pycharm.py， 规模写在 configs/model_pilot.yaml。完整协议需要 GPU：安装 requirements.txt、准备 Qwen3-0.6B 权重、改三份配置路径后执行 python -m src.run_all --stage model，届时 9 个 pending 记录会被同名 measured 替换。依赖缺失时脚本明确报错退出，不会写入任何伪造指标。

本报告由 src/core/tech_report.py 从 reports/results.jsonl 与 reports/algo_lab_curves.json 生成。所有 measured 数字均为真实执行结果； CPU pilot 数字来自真实权重执行，完整协议的 9 个指标仍为 pending。
