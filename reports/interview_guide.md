# 面试对答手册（大模型算法岗）

右键 `show_results_pycharm.py` 可以打印全部数字，右键 `algo_lab_pycharm.py` 可以现场跑一遍 SFT 到 DPO。下面的数字都来自 `results.jsonl`，改了数据源就要重看一遍。算法岗专项推导与追问见 `algorithm_interview.md`。

## 一句话定位

中文数学大模型后训练算法与可信评估，完整链路是参数化数据、三态验证器、LoRA-SFT、DPO、序列级 KL 诊断与四类泛化子集上的生成评测。这是大模型算法岗求职作品集，转行期间自修的工程内容，与博士后期间的分布依赖随机过程研究分栏表述，不合并叙述。

## 30 秒陈述

我做的是一条中文数学后训练的完整链路，LoRA-SFT 加 DPO，从参数化题目生成、assistant-only loss mask、显式冻结 SFT 参考模型，一直做到严格验证器和四个泛化子集上的生成评测。复现的时候看到 reward margin 单调上升，生成准确率却从 62.5% 退回 50%，追下去是偏好数据里没有真数学错误、40 条测试集其实是 2 道题、验证器用子串包含判对，三者叠加。

为了让目标函数层面的性质在没有 GPU 的机器上也能验证，我另写了一个可解析梯度的策略实验台，CPU 上真跑 SFT 最大似然与 DPO 梯度下降，梯度用有限差分校验。三组偏好对照里，shortcut 组把梯度花在长度上，长度偏置劫持率 0.7241，去混淆组降到 0.1864，而三组 reward accuracy 全是 1.0000，训练指标完全看不出差别。此外我在真实的 Qwen3-0.6B 权重上跑了一个明确缩减规模的 CPU pilot，LoRA-SFT、显式冻结 SFT ref 的 DPO、masked loss、三态生成评测和序列级 KL 都真实执行过，adapter 哈希和逐条预测落了盘。这个现象再用可识别性、聚类推断和验证器偏差校正三个估计量解释清楚。

## 2 分钟讲述

动机来自一次失败的复现。旧项目报告 teacher-forced loss 从 4.41 降到 2.50，看上去效果很好，但自由生成的符号准确率是 Base 50%、SFT 62.5%、DPO 50%，DPO 退化回起点。更麻烦的是三份报告对同一个模型给出三个互相矛盾的 PPL，跨度超过 42，仓库里保存的 adapter 也无法解释那组最好看的数字。

我先做了审计。去掉题目编号后缀之后，40 条测试集只剩 2 道不同的题。旧评测器判对的 65 条里，用严格验证器重判有 32 条是假阳性，而且 exact 和 symbolic 两列逐条 120 比 120 完全相同，说明 SymPy 分支一次都没生效过。偏好数据里 80 条标成"错误答案"的样本，答案其实全对，因为生成错误答案的代码是 `ans.replace("4","5",1)`，而训练集的四个答案里没有字符 4。所有 chosen 都比 rejected 长 18 到 28 个字符，所以 reward accuracy 等于 1 只说明模型学会了长度。

然后我重建了算法链路。数据换成 600 道参数化中文数学题，12 个题型族，每题唯一参数组，答案由 oracle 算完再用第二条计算路径交叉验证，测试集分出未见参数、同义改写、反事实、未见题型四个子集。评测器改成受限语法的精确解析，correct、incorrect、unverifiable 三态，解析失败绝不回退字符串匹配。SFT 只对 assistant completion 算 NLL，用 offset_mapping 在字符级定位 prompt 边界。DPO 用独立基座实例加载冻结的 SFT adapter 作参考模型，训练前逐参数断言 ref 与 policy 初值一致。

算法层我单独做了一层可跑的验证。把策略写成候选集上的 log-linear 模型，配分函数可算，于是 SFT 的 MLE 梯度、DPO 的梯度、序列级 KL 都有闭式解。解析梯度和中心有限差分的最大误差在 1e-11 量级。三组偏好数据真跑下来，reward accuracy 都是 1.0000，margin 都上升，但 shortcut 组的长度偏置劫持率 0.7241、质量系数 2.0335，去混淆组劫持率 0.1864、质量系数 2.8226。参考模型锚错到 base 时 KL 从 0.0513 涨到 0.5179。固定策略下 margin/beta 的变异系数是 0.0000，证明它只是恒等式，真正训练后是 0.5727，说明 beta 改变的是优化轨迹。

三个子贡献把假象拆成可估计的量。第一，用只用表面特征的分类器做交叉验证，shortcut 组 AUC 是 1.0000，长度和格式匹配、只有数学内容错误的 deconfounded 组是 0.5000，并写了一个命题说明偏好标签被表面特征确定性解释时 DPO 损失在质量方向不可识别。第二，用 ANOVA 估簇内相关，ICC 0.7368，设计效应 15，有效样本量 2.6667，iid 区间 [0.0212, 0.2288] 换成聚类区间 [0.0000, 0.2500] 之后结论从"显著"变成"不能拒绝无提升"，要检出 5 个百分点需要约 99 个独立簇。第三，用真值已知的 calibration 和 survey 估验证器的 FPR 与 FNR，旧式宽松验证器 FPR 0.5000，观测准确率 0.7425 相对真值 0.6625 高估 0.0800，校正后 0.6496、偏差 -0.0129，bootstrap 区间覆盖真值。

权重层我也在真实的 Qwen3-0.6B 上跑了 CPU pilot。20 步 LoRA-SFT 把 masked test NLL 从 2.5602 降到 1.2551，参考模型用独立基座实例加载冻结的 SFT adapter，逐参数断言通过 422 个共享参数。三组 DPO 的 reward margin 分别上升 0.3617、0.1260、0.5432，序列级 KL 用采样估计。规模缩减写在 `configs/model_pilot.yaml`，5 道题、96 个生成 token，所以这些数字只证明链路执行，不是能力结论。

边界我说在前面。三层验证分得很清楚：算法层是 7 维解析策略，验证目标函数；权重层是真实 Qwen3-0.6B 上的 CPU pilot，缩减规模写在配置里，只证明链路可执行，不作为能力结论；完整协议层是 256 token、303 题的正式评测，本机 CPU 跑不完，9 个 `model_stage` 指标仍是 `pending_model_run`，一个数字都没编。pilot 的实测数字记在 `model_pilot` 实验，绝不替换那 9 个 pending。有 GPU 跑完完整协议后才会替换。

## 白板上能写的三块

log-linear 策略下配分函数在同一 prompt 的成对比较里抵消，令 $\Delta=(\theta-\theta_{\rm ref})\cdot(\phi^+-\phi^-)$，则

$$L(\theta)=-\mathbb E\log\sigma(\beta\Delta),\qquad \nabla_\theta L=-\beta(1-\sigma(\beta\Delta))(\phi^+-\phi^-).$$

质量 $Q$ 只能通过回答文本进入似然。观测等价的构造是让 $\log\pi_{\theta'}(y|x_i)=\log\pi_\theta(y|x_i)+c_i$ 对 $\mathcal D$ 中出现的回答成立，概率质量从 $\mathcal D$ 之外的回答重分配得到，于是 $\Delta_{\theta'}=\Delta_\theta$、$L(\theta')=L(\theta)$。把 $\theta$ 分成 $(\phi,\psi)$，似然只依赖 $\phi$，关于 $\psi$ 的 Fisher 信息为零。

簇结构用 $\mathrm{deff}=1+(m-1)\rho$ 和 $n_{\rm eff}=n/\mathrm{deff}$。功效反解是 $K\ge\big((z_{1-\alpha/2}+z_{1-\beta})\sigma_{\rm cluster}/\delta\big)^2$。这里 $n=40$、$K=2$、$m=20$、$\rho=0.7368$，所以 $\mathrm{deff}=15$、$n_{\rm eff}=2.6667$。

验证器误判用 $p̂=(1-\mathrm{FNR})\pi+\mathrm{FPR}(1-\pi)$，反解 $\hat\pi=(p̂-\mathrm{FPR})/(1-\mathrm{FPR}-\mathrm{FNR})$。实测 FPR 0.5000、FNR 0.1267，分母 0.3733，所以校正会把抽样误差放大，区间从观测层面直接给的窄区间变成 [0.5099, 0.8050]，这个代价要主动讲。

## A 组：算法岗必答

**A1. 你到底跑没跑 DPO 训练？**
跑了三层里的前两层。算法机制层在 CPU 上真跑 SFT 最大似然和 DPO 梯度下降，解析梯度用中心有限差分校验，有完整曲线。权重层用真实 Qwen3-0.6B 加 LoRA 跑了缩减规模的 CPU pilot，SFT 步数、偏好对数、评测题数、生成长度都写在 `configs/model_pilot.yaml`，逐条预测和 adapter 哈希落了盘，参考模型逐参数断言过。第三层完整协议需要 GPU，9 个指标明确标 pending。pilot 数字不能当能力结论。

**A2. 为什么用 log-linear 策略而不是真 transformer？**
要验证的是目标函数的性质，不是模型容量。这个策略的配分函数可算，DPO 梯度和 KL 都有闭式解，能把"beta 是缩放还是改变优化""ref 锚错差多少"从口径争论变成可计算的数字。真实模型里 Z 不可算，KL 必须采样估计，`diagnostics.py` 给的就是按 prompt 聚类的 MC 估计与区间。

**A3. 从 RLHF 推到 DPO，再写出梯度。**
带 KL 约束的最优解是 $\pi^*\propto\pi_{\rm ref}\exp(r/\beta)$，反解 $r=\beta\log(\pi_\theta/\pi_{\rm ref})+c(x)$，代入 Bradley-Terry 得到成对分类损失。同一 prompt 下 $Z_\theta(x)$ 抵消，梯度就是 $-β(1-σ(βΔ))(φ^+-φ^-)$。完整推导在 `algorithm_interview.md`。

**A4. ref 为什么必须是 SFT？**
TRL 在 ref_model=None 且 policy 是 PeftModel 时会 disable adapter，锚点变成未训练 base，KL 惩罚把 SFT adapter 参数当作可直接优化的变量。实验台上锚错使 KL 从 0.0513 升到 0.5179。修正版用独立基座实例加载冻结的 SFT adapter，训练前逐参数断言 ref 与 policy 初值一致。

**A5. beta 怎么调？**
不看 reward margin。固定策略时 margin 就是 beta 乘 log-ratio 差，实验台上变异系数 0.0000，纯恒等式。真训练时 beta 改变梯度尺度与收敛位置，要看序列级 KL 和下游准确率，四个 beta 下 KL 跨度 0.1276。

**A6. LoRA 的 B 为什么零初始化，rank 怎么选？**
零初始化保证训练起点等于基座，SFT 的 ref 才有意义。rank 决定低秩子空间容量。本项目没做 rank 消融，简历里不写这一项。真要做应该固定数据、beta 与步数，按题目簇给配对区间，而不是只看训练集 loss。

**A7. DPO 和 PPO、GRPO 怎么选？**
DPO 不需要显式 reward model 和在线采样，工程成本最低，但对偏好数据质量极敏感，这个项目量化的正是这个敏感性。PPO 需要 reward model 与 value net，GRPO 用组内相对优势省掉 value net，两者在线采样、能持续探索，代价是算力与实现复杂度。小样本弱验证器场景下先修数据和评测更划算。

**A8. 生成评测协议是什么？**
关闭 thinking，max_new_tokens 至少 256，严格抽取最终答案，解析失败记 unverifiable 而不回退字符串匹配，按未见参数、同义改写、反事实、未见题型四个子集分别报准确率，按题目簇给区间。旧项目用 64 token 截断把没写完答案全记成数学错误，这条已修掉。

**A9. 长度偏置怎么检测？**
训练前用只用表面特征的交叉验证 AUC 体检偏好数据，shortcut 组 1.0000，去混淆组 0.5000。训练后用对抗探针让"短的正确"与"明显更长的错误"二选一，shortcut 组劫持率 0.7241，去混淆组 0.1864。

**A10. 0.6B 这么小，结论有意义吗？**
算法层验证的是目标函数性质，与模型规模无关。模型层选 0.6B 是为了 CPU 上也能复现，而偏好数据里没有真错误、测试集只有 2 道题这类结构性缺陷，换更大的模型不会自动消失。

## B 组：项目与统计追问

**B1. 这不就是 debug 吗，创新在哪？**
只把子串匹配换成严格解析确实是 debug。我做的是把三个失效各自抽象成可度量的量，偏好标签被表面特征解释的程度用交叉验证 AUC 和 shortcut index 刻画，伪重复用 ICC 和设计效应刻画，验证器误判用 FPR/FNR 和校正估计量刻画。这样结论不依赖某个模型或某份数据，可以迁移到任何小样本后训练评测。最有价值的是把旧项目那次"调参失败"解释成三重偏差的必然结果，并用命题说清为什么 reward accuracy 等于 1 与数学能力无关。

**B2. 为什么没有完整协议的模型结果，是不是跑不起来？**
不是跑不起来，是 CPU 跑 303 题 × 256 token 不现实。本机其实有 CPU 版 torch 和完整 Qwen3-0.6B 权重，所以我跑了缩减规模的 pilot，把链路真实执行了一遍，数字在 `model_pilot` 实验里。完整协议 9 个指标仍是 `pending_model_run`，一个没编。算法层、pilot 层和完整协议层三件事分开讲，比含糊地说「模型层跑通了」更可信。

**B3. 可识别性命题是不是废话，损失函数里本来就没有 Q？**
有恒等式的成分，但它的作用是把数据构造和目标函数连起来。DPO 损失里当然没有 Q，Q 只能通过 $(x,y^+,y^-)$ 的文本进入。如果构造偏好对时让标签与 Q 在给定表面特征后条件独立，Q 方向的参数在似然里完全没有信息，Fisher 信息为零。这个说法把"偏好数据要多样"从经验建议变成可识别性条件。实验上 shortcut 组 AUC 1.0、去混淆组 0.5、旧项目 240 条 1.0，重排 Q 后损失逐位不变。

**B4. KL 锚点会不会让 Q 重新可识别？**
不会改变结论。KL 约束的是策略相对 ref 的整体偏离幅度，相当于给解加范数限制，没有引入关于 Q 的新信息，因为 ref 是 SFT 模型，它本身也是在同一批不含 Q 信号的数据上训出来的。它把观测等价类收缩成一个球与该类的交集，但这个交集里仍然存在 Q 表现任意的解。length_reversed 组 AUC 仍是 1.0 也说明，只要表面线索还在，改变线索方向不改变可分性，只改变符号。

**B5. 二值结果用 ANOVA 估 ICC 合适吗？**
是常用近似，等价于把簇内相关当作随机效应的方差分量比，对二值数据并不精确。这里簇内结果几乎完全一致，组内方差趋近 0，我把估计 clip 到 [0,1]。实测 0.7368 而不是 1.0，是因为 SFT 在二次函数那道题上有 25% 的样本答对，组内出现了方差。更严谨的是广义估计方程或二值随机效应模型，我在报告里把它列为方法边界，没有声称估计精确。

**B6. 只有 2 个簇，bootstrap 有意义吗？**
恰恰是要说明它没意义。2 个簇的重采样只能产生有限几种组合，区间 [0.0000, 0.2500] 离散且宽，下界压在 0 上。它的用途不是给出精确不确定性，而是证明把 40 条当 iid 得到的 [0.0212, 0.2288] 是虚假的精确。一个不跨 0 一个跨 0，结论从"显著"变成"不能拒绝无提升"，这才是重点。功效分析进一步给出要检出 5 个百分点需要约 99 个独立簇。

**B7. McNemar 和聚类区间是不是矛盾？**
不矛盾。McNemar 精确 p 是 0.0625，三个两两比较做 Holm 之后最小变成 0.1875，本来就不显著。聚类区间 [0, 0.25] 包含 0，方向一致。看起来不一致的是 iid 正态区间 [0.0212, 0.2288]，那个是错误地把 20 个伪重复当独立样本算出来的。

**B8. 功效分析里只有两个簇，方差可靠吗？**
不可靠。$\sigma_{\rm cluster}$ 是两个簇各自配对差值均值的样本标准差，只有两个点。所以我在结果里把它标成基于观测簇间方差的情景分析，不是可靠的方差估计。它的用途是给量级：即使按这个偏小的方差，检出 5 个百分点也要约 99 个独立簇，真实方差更大时只会更多。

**B9. 偏差校正的前提是什么？**
三个。一是 FPR 与 FNR 在 calibration 和 survey 上相同，我让两类样本由同一套生成器按相同比例构造，等价形式的比例也一致。二是观测准确率的定义把 UNVERIFIABLE 算作没判对，报告里写明了。三是 $1-\mathrm{FPR}-\mathrm{FNR}$ 不能接近 0，否则校正放大抽样误差。实测分母只有 0.3733，校正后区间 [0.5099, 0.8050] 明显变宽，这是方法本身的代价，我把它写进结果而不是藏起来。

**B10. 三个 verifier 条件独立吗？**
严格说不成立，它们共享题面语言。我做了两件事。把 verifier 从 2 个提到 3 个，因为 $J=2$ 时 $2^J-1=3$ 个自由模式频率对应 $1+2J=5$ 个参数，模型欠识别，EM 只会收敛到边界，$J=3$ 时 $7=7$ 恰好识别。再以 0、0.2、0.5 的概率把第三个 verifier 的判定替换成第一个来制造误差相关，$\hat\pi$ 从 0.8682 到 0.8753，幅度 0.0072。在这个数据上结论对相关性不敏感，但我不会说它一般成立。

**B11. 既然丢弃 UNVERIFIABLE 有偏差，为什么还做 latent class？**
因为这正是要暴露的偏差。EM 只能用三个 verifier 都给出二元判定的样本，覆盖率 0.7425，被丢掉的几乎都是没有最终答案标记的错误输出，属于 MNAR 而不是随机缺失。结果子集真值比全集高 0.2298，我把这个选择偏差单独记进结果文件。这里的结论不是"EM 很准"，而是"直接丢掉不可核验样本再报准确率会系统性高估"。

**B12. 严格 verifier 的 UNVERIFIABLE 率那么高，会不会把好答案误判掉？**
会。旧项目 120 条生成输出里严格 verifier 判 33 条 correct、87 条 unverifiable，主要因为 64 token 截断没写完答案，以及受限语法不接受复杂 LaTeX 和单位。我没有把它折进 incorrect，也没有偷偷回退到字符串匹配，而是作为独立第三态并在偏差校正里显式建模。新协议把 max_new_tokens 提到 256 就是为了减少这类缺失。这是精确性与覆盖率的取舍，我选精确。

**B13. 长度相等了，模型会不会学别的 shortcut？**
有可能，所以表面特征里除了长度差还放了格式标记差、LaTeX 标记数差、数字个数差、标点差、换行差，六维联合的交叉验证 AUC 是 0.5000。我没法排除更高阶线索，这也是 length_reversed 组存在的原因：它的 AUC 仍是 1.0 但线索方向与正确性相反。算法层的对抗探针已经给出方向性证据，权重层的下游对照要等 GPU。

**B14. length_reversed 组 AUC 还是 1.0，说明什么？**
说明表面线索仍完全可分，只是方向反了。这个组不是用来降低 SI 的，而是做符号检验。算法层上它的长度系数是负的、劫持率 0.0720，和 shortcut 组方向相反，验证了这个对照确实在测符号而不是幅度。

**B15. 为什么用 AUC 而不直接看下游表现？**
AUC 是不需要训练就能算的诊断量，回答"这批偏好数据本身有没有关于质量的信息"，属于训练前的数据体检。下游更直接但需要 GPU，我现在用算法实验台补上了 CPU 可跑的一层。两者互补，AUC 用来在训练前否决一批数据，下游对照用来验证否决是否正确。

**B16. 和 reward hacking、length bias 的已有工作有什么区别？**
已有工作多是指出 DPO 有长度偏置，或报告 reward 上升质量下降。我这里把它拆成三个可分别估计的来源，并给出各自的估计量与区间：偏好信号的可识别性、评测集的聚类结构、验证器的误分类。后两个通常被当成实验卫生问题，我当统计推断问题处理，给出有效样本量、功效曲线和偏差校正估计量。算法层还额外给出目标函数层面的可复现证据。

**B17. 工业界怎么用？**
三件具体的事。上线前给偏好数据做体检，表面特征基线 AUC 接近 1 就说明这批数据只能教格式。评测集做样本量规划，用簇内相关算有效样本量，别把同一道题的改写当独立样本，否则 A/B 结论假阳性。自动评测器定期校准，用一小批人工标注估 FPR/FNR，把观测准确率还原成真实准确率再报。都不需要额外训练成本。

**B18. 给你 GPU，下一步做什么？**
先跑三组 DPO 的下游对照，看去混淆偏好对在真实权重上是否也把梯度从长度转到正确性，同时把序列级 KL 的 MC 估计与解析实验台的结论对齐。再在 CMATH、Math23K 或 GSM8K 中文子集上重复整套诊断，看结论是否迁移。然后是把可识别性检验接到偏好数据构造闭环里，自动生成长度与格式匹配的 hard negatives。

**B19. 哪部分是非统计科班做不出来的？**
不是公式，是三个判断习惯。看到 40 条测试集先问独立单位是什么，而不是直接算比例。看到验证器报准确率先问它的假阳性率，而不是当金标准。看到 reward margin 随 beta 线性增长先检查是不是恒等式，而不是当调参发现。这些是训练形成的反应，不是工具。

**B20. 为什么用 0.6B，不换更大的模型？**
算法层的问题在目标函数，模型层的问题在评估方法，都不在模型能力。0.6B 足够跑通 SFT 和 DPO，CPU 上还能复现。换大模型只会让 loss 下降更好看，不会改变偏好数据里没有真错误、测试集只有 2 道题这些结构性缺陷。

**B21. assistant-only loss mask 具体怎么做的？**
用 chat template 分别生成完整对话和只到 prompt 的文本，断言前者以后者为前缀，再用 fast tokenizer 的 offset_mapping 在字符级定位 prompt 长度，把字符起点小于该长度的 token 的 label 设成 -100。不用 token 级前缀断言，因为 BPE 在 prompt 与 completion 交界处可能合并出不同 token。总 NLL 按 token 加权，不是样本等权平均。

**B22. beta 到底怎么调？**
不能看 reward margin，margin 等于 beta 乘 log-ratio 差，随 beta 线性增长是恒等式，实测 margin/beta 变异系数 0.0016 而 test loss 只动 0.005。要看真正的 KL，用从策略采样的 $\log\pi_\theta-\log\pi_{\rm ref}$ 均值做无偏估计，按 prompt 聚类给 bootstrap 区间，再结合下游生成准确率决定。算法层因为配分函数可算，KL 是精确值，可以直接对照 MC 估计的行为。

**B23. 简历里写"有效样本量 2.67"会不会显得项目很小？**
那个数字说的是旧项目的缺陷，不是新项目的规模。新数据集 600 道唯一题、12 族、3 个未见族、测试集四个泛化子集，算法层还有 252 条 SFT 指令与 120 道对抗探针。2.67 是反面对照，写的时候要跟在明确动作后面，说明我复算了旧结论并给出它需要多少独立簇才能成立。

**B24. 9 个指标 pending，会不会觉得没做完？**
我会主动先说，不等面试官发现。算法层、三个子贡献和权重层 CPU pilot 的 measured 记录都完整可复现，只有完整协议受算力限制没跑。我会说明哪些结论不依赖权重、哪些是 pilot 的链路验证、哪些必须等 GPU，并且不把 pending 数字或 pilot 的缩减数字写进简历当能力结论。把边界讲清楚比含糊带过更能建立信任。

**B25. 这个项目和你博士后的研究什么关系？**
没有数据或成果上的关系，是转行期间自修的工程作品集。博后做的是分布依赖随机过程，简历里分栏写，面试里分开讲。我不会把自修的 LLM 工程内容包装成科研成果。
